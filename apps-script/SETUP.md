# 本番運用の設置手順

構成はシンプルです。お客様のスマホ → 静的なWebページ → Google Apps Script → スプレッドシート / Drive / メール。サーバーもデータベースも不要で、全部がお店のGoogleアカウントの中に収まります。

```
お客様のスマホ（QR / LINEでURLを開く）
        │  送信（回答 + 圧縮済み写真）
        ▼
Apps Script Web App  ──→ スプレッドシート（器 1点＝1行）
                     ──→ Drive（案件ごとのフォルダに写真 + answers.txt）
                     ──→ 担当者へメール通知
```

お客様は1回の送信で複数の器（アイテム）をまとめて登録できます。店舗情報・納品情報は1回だけの入力で、器の仕様だけを「＋ もう1点追加する」で繰り返せます。

## 1. 受け皿を作る

1. Googleドライブで**スプレッドシート**を新規作成（[sheets.new](https://sheets.new) を開くだけでOK）。URLの `/d/` と `/edit` の間がシートIDです。控えておいてください。
2. 写真の保存先フォルダはすでに用意済みです：[このDriveフォルダ](https://drive.google.com/drive/folders/1unUjWdgtqUFw1XVnQ_oGca0AgY0WaOhT)（`apps-script/Code.gs` の `DRIVE_ID` に設定済み）。

## 2. Apps Script を設置する

1. [script.google.com](https://script.google.com) で新しいプロジェクトを作成。
2. このリポジトリの `apps-script/Code.gs` の中身をまるごと貼り付ける（`DRIVE_ID` と通知メール宛先は設定済みです）。
3. 冒頭の `SHEET_ID` だけ、手順1で控えたスプレッドシートIDに書き換える。

   | 定数 | 内容 | 状態 |
   | --- | --- | --- |
   | `SHEET_ID` | 手順1のスプレッドシートID | **要編集** |
   | `DRIVE_ID` | 写真の保存先フォルダ | 設定済み |
   | `MAIL_TO` | 通知メールの宛先（s.y.connect.co@gmail.com） | 設定済み |
   | `MAIL_CC` | 通知メールのCC（m.yuri0713@gmail.com） | 設定済み |

4. 右上の **デプロイ → 新しいデプロイ → 種類：ウェブアプリ**。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**（お客様はログインせずに送信するため）
5. 初回は権限の確認画面が出ます。Drive・スプレッドシート・メール送信を許可してください。
6. 発行された `https://script.google.com/macros/s/…/exec` をコピー。

## 3. アプリに送信先を設定する

手順2でコピーしたURLをClaudeに伝えてください。アプリ（`index.html`）の送信先デフォルト値として組み込み、GitHub Pagesに反映します。空のままだとデモ送信（実際には送られない）のままです。

設定するとアプリ側の挙動が変わります。

- 「この内容で送信する」で実際にPOSTし、送信中はボタンがロックされます。
- 失敗すると赤い帯でエラーを出し、下書きは残ります。お客様はそのまま再送できます。
- 成功すると受付番号を表示し、下書きを消去します。

## 4. 公開してQRにする

このページを静的ホスティング（お店のサイトのサブディレクトリでも、Netlify/Vercel/GitHub Pagesでも可）に置き、そのURLをQRコードにしてご案内に印刷、またはLINEで送ります。スマホのブラウザで開くだけで、インストールは不要です。

このリポジトリは GitHub Pages で公開する構成になっています。`main` ブランチの Pages を有効にすると、`index.html` がそのまま公開されます。

## データの入り方

**スプレッドシート**は**器 1点＝1行**です。1回の送信で3点の器を登録すれば、同じ受付番号で3行追加されます。先頭に受付日時・受付番号・**器 No.（例：`2 / 3`）**・お店の名前・案件名・ご担当者・連絡先・Driveフォルダのリンク・写真枚数（送信全体の合計）が並びます。そのあとに店舗・ブランドコンセプト＋製作スケジュールの設問（全行共通）、続けて器仕様の設問（その行の器だけの内容）が列として続きます。

同じ受付番号でフィルタ・グループ化すれば1回の送信内容がまとまり、器ごとに見たいときは「器 No.」列でそのまま並び替えできます。

**Drive**は `2026-08-16 紬 銀座 TSM-2026-4821` のように案件ごとにフォルダができ、直下に `logo.jpg` `atmos.jpg`（店舗共通の写真）、器ごとに `器1` `器2`…のサブフォルダに `ref1.jpg`〜`ref3.jpg`、そして送信全体の回答をまとめた `answers.txt` が入ります。写真のメモ（「ポイント：」欄）は各ファイルの説明に入るので、Driveのプレビューからそのまま読めます。

## 運用上の注意

- 写真は送信前に長辺1600pxのJPEGへ圧縮されます。店内の暗い写真でも十分な情報量で、1件あたり数百KB程度に収まります。
- 送信は `mode: 'no-cors'` で行うため、ブラウザ側では成功／失敗の詳細を受け取れません。Apps Script側の実行ログ（左メニューの「実行数」）が実際の記録です。
- 下書きはお客様の端末のブラウザにのみ保存されます。端末を変えると引き継げないため、別端末での再開が必要なら「メールで続きのURLを送る」機能の追加をご検討ください。
- Code.gs を編集したら、**新しいデプロイ**を作らないと反映されません（既存デプロイの「編集 → バージョン：新規」でも可）。
